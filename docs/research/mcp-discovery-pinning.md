# MCP discovery and package pinning

**Evidence snapshot:** 2026-09-02. This report combines first-party documentation and source/package metadata with read-only inspection of the installed clients and configuration files. Credential values were neither recorded nor reproduced; authentication evidence is limited to owning paths and data categories.

## Executive answer

The machine does not have one shared MCP authority today. OMP, Claude Code, Codex/ChatGPT desktop, Copilot CLI, VS Code, and Pi's adapter each have distinct discovery rules. OMP and the Pi adapter deliberately import other clients' files, while Copilot CLI explicitly does not read VS Code's `.vscode/mcp.json`. Same-name precedence is documented for OMP, Claude Code, Copilot CLI, and Pi's adapter; Codex documents its general configuration hierarchy; VS Code documents scopes but not collision precedence. Classic Claude Desktop has only a user file in the reviewed documentation. [OMP discovery](https://github.com/can1357/oh-my-pi/blob/main/docs/mcp-config.md#discovery-and-precedence), [Claude Code scopes](https://code.claude.com/docs/en/mcp#mcp-installation-scopes), [Codex configuration](https://developers.openai.com/codex/config-reference), [Copilot CLI project discovery](https://docs.github.com/en/copilot/how-tos/copilot-cli/customize-copilot/add-mcp-servers#adding-per-repository-mcp-servers), [VS Code configuration](https://code.visualstudio.com/docs/agent-customization/mcp-servers#_configure-the-mcpjson-file), [Pi adapter 2.10.0](https://github.com/nicobailon/pi-mcp-adapter/blob/v2.10.0/README.md#quick-start)

There is also no MCP-specific package lock shared by these clients. File-based clients pass a `command`, argument list, or URL to the underlying runtime. For npm-backed stdio servers, an exact `package@version` is a supported npm package spec, while `@latest`, an unversioned package name, and semver ranges are mutable. A literal remote URL fixes the address only; none of the reviewed clients documents cryptographic pinning of the service implementation or its tool schema. [npm package specs](https://docs.npmjs.com/cli/v11/using-npm/package-spec), [OMP fields](https://github.com/can1357/oh-my-pi/blob/main/docs/mcp-config.md#supported-server-fields), [Claude Code install forms](https://code.claude.com/docs/en/mcp#installing-mcp-servers), [Codex fields](https://developers.openai.com/codex/mcp#stdio-servers), [Copilot CLI configuration](https://docs.github.com/en/copilot/how-tos/copilot-cli/customize-copilot/add-mcp-servers#editing-the-configuration-file), [VS Code reference](https://code.visualstudio.com/docs/agents/reference/mcp-configuration)

## Client discovery, precedence, enablement, cache, and authentication

### OMP 18.1.2

- **Discovery and precedence.** OMP-native ownership is project `.omp/mcp.json` (compatibility `.omp/.mcp.json`) and active-profile user `~/.omp/agent/mcp.json` (compatibility `.mcp.json`). It additionally imports Claude Code, Claude plugins, Codex, Gemini, OpenCode, Cursor, Windsurf, VS Code project config, OMP packages, and root `mcp.json`/`.mcp.json`. Providers are evaluated in documented priority order; the first complete same-name definition wins and entries are not field-merged. Project entries generally precede same-client user entries, with OpenCode called out as the exception. [OMP preferred locations and imports](https://github.com/can1357/oh-my-pi/blob/main/docs/mcp-config.md#preferred-config-locations), [OMP precedence](https://github.com/can1357/oh-my-pi/blob/main/docs/mcp-config.md#discovery-and-precedence)
- **Enablement.** Per-server `enabled: false` skips a server. The active-profile user file may contain `enabledServers` and `disabledServers`; the denylist has highest priority. Project-config discovery can also be disabled with OMP's `mcp.enableProjectConfig` setting. [OMP file shape](https://github.com/can1357/oh-my-pi/blob/main/docs/mcp-config.md#file-shape), [OMP precedence](https://github.com/can1357/oh-my-pi/blob/main/docs/mcp-config.md#discovery-and-precedence)
- **Cache/lifecycle.** `/mcp reload`, `test`, `reconnect`, `reauth`, and `unauth` are explicit controls. Values produced by `!command` expansion are process-lifetime cached. The reviewed guide does not document a persistent MCP tool-catalog cache. [Dynamic values](https://github.com/can1357/oh-my-pi/blob/main/docs/mcp-config.md#dynamic-secrets-environment-variables-and-command-expansion), [TUI controls](https://github.com/can1357/oh-my-pi/blob/main/docs/mcp-config.md#manage-servers-in-the-tui)
- **Authentication storage.** Managed OAuth refresh material lives outside project config in the active profile's auth storage, `agent.db` or an auth broker, keyed deterministically by profile and server URL. An explicit authorization header wins. OMP accepts `apikey` metadata but does not inject an API key from auth storage. [OMP auth](https://github.com/can1357/oh-my-pi/blob/main/docs/mcp-config.md#auth)
- **Local evidence.** `~/.omp/agent/mcp.json` exists. The adjacent `~/.omp/agent/agent.db` is the documented category of local auth storage. No project OMP MCP file exists in `agentlens`.

### Claude Code 2.1.241

- **Discovery and precedence.** Local scope (the default, private to the current project) and user scope are stored in `~/.claude.json`; team-shared project scope is root `.mcp.json`. Same-name priority is local, project, user, plugin, then managed `claude.ai` connector, and definitions are not merged. [Claude Code installation scopes](https://code.claude.com/docs/en/mcp#mcp-installation-scopes)
- **Enablement/trust.** Project servers require workspace trust and explicit approval. `enabledMcpjsonServers`, `disabledMcpjsonServers`, `enableAllProjectMcpServers`, per-project disabled servers, managed policy, and strict `--mcp-config` loading affect availability. A cloned repository cannot approve its own server before the workspace is trusted. [Project approvals](https://code.claude.com/docs/en/mcp#project-server-approvals-and-workspace-trust), [server status](https://code.claude.com/docs/en/mcp#server-status)
- **Cache/lifecycle.** Since 2.1.221, the optional discovery cache can expose a saved tool list at session start and defer the connection until first use. In the installed version range it is off by default unless gradual rollout enables it; `MCP_DISCOVERY_CACHE=1|0` overrides rollout. Reconnect and clear-auth have documented invalidation behavior. [Claude Code cache](https://code.claude.com/docs/en/mcp#server-status-detail)
- **Authentication storage.** OAuth client secrets are stored in macOS Keychain or a credentials file rather than MCP config. Sign-ins are endpoint-specific, and `claude mcp logout` clears stored credentials. [OAuth credentials](https://code.claude.com/docs/en/mcp#use-pre-configured-oauth-credentials), [same-name endpoint warning](https://code.claude.com/docs/en/mcp#configuration-warnings)
- **Local evidence.** `~/.claude/.claude.json` has an empty `mcpServers` object for `agentlens`, and `agentlens` has no `.mcp.json`. Therefore Claude Code currently discovers no project/user MCP owned by this repository.

### Claude Desktop (classic Chat surface)

- **Discovery.** The first-party MCP quickstart documents the macOS user file `~/Library/Application Support/Claude/claude_desktop_config.json`, loaded after restarting Desktop. It does not document a project scope or same-name precedence for this classic surface. [MCP quickstart](https://modelcontextprotocol.io/docs/2026-07-28/develop/connect-local-servers#access-developer-settings)
- **Lifecycle/cache and enablement.** The quickstart says configured stdio servers start with Desktop and configuration changes require a restart. It does not specify a persistent discovery cache or a separate enable/disable store. [Desktop server startup](https://modelcontextprotocol.io/docs/2026-07-28/develop/connect-local-servers#installing-the-filesystem-server)
- **Authentication storage.** The reviewed first-party guide does not identify a physical MCP OAuth store. The local application data at `~/Library/Application Support/Claude/config.json` contains an application OAuth token-cache category, but this inspection cannot establish that it is an MCP credential store.
- **Local evidence.** `claude_desktop_config.json` contains preferences but no `mcpServers`; it owns none of the observed MCPs.

### Codex CLI 0.144.1, ChatGPT desktop, and the Codex VS Code integration

- **Discovery and precedence.** ChatGPT desktop, Codex CLI, and the IDE extension share MCP configuration for the same Codex host. The default is `~/.codex/config.toml`; trusted projects may add `.codex/config.toml`. Codex's overall configuration hierarchy puts command-line and profile values above project config, then user config, then system config and built-in defaults; project config cannot override some machine-local or host-managed restrictions. [Codex MCP](https://developers.openai.com/codex/mcp), [configuration hierarchy](https://developers.openai.com/codex/config-reference)
- **Enablement/lifecycle.** A server can set `enabled`, `required`, tool allow/deny lists, startup timeout, and tool timeout. The app and IDE UI require host/extension restart after adding a server. The reviewed first-party docs do not specify a persistent MCP tool-discovery cache or package-update lifecycle. [Codex MCP options](https://developers.openai.com/codex/mcp#other-configuration-options)
- **Authentication storage.** Remote servers may use an environment-sourced bearer token, static/environment-sourced headers, or stored OAuth initiated by `codex mcp login`. Client ID and callback metadata may be stored in `config.toml`; the reviewed MCP page calls tokens “stored MCP OAuth credentials” but does not identify their backing keychain or file. [Codex HTTP authentication](https://developers.openai.com/codex/mcp#streamable-http-servers), [OAuth callbacks](https://developers.openai.com/codex/mcp#oauth-client-registration-and-callbacks)
- **ChatGPT web is separate.** ChatGPT web does not read local Codex files. Custom MCP apps are remote endpoints configured and published in workspace/user settings. Publishing freezes the available tool/input schema until an admin refreshes and republishes; it does not pin the remote implementation. [Codex/ChatGPT surface distinction](https://developers.openai.com/codex/mcp), [ChatGPT MCP app updates](https://help.openai.com/en/articles/12584461-developer-mode-and-mcp-apps-in-chatgpt#do-mcp-app-changes-auto-update-in-my-workspace)
- **Local evidence.** `~/.codex/config.toml` owns `node_repl` as an enabled stdio server whose executable is inside `ChatGPT.app`; its environment points at a versioned ChatGPT browser-plugin bundle. It also declares `computer-use` disabled. No project `.codex/config.toml` exists in `agentlens`.

### GitHub Copilot CLI 1.0.59

- **Discovery and precedence.** User definitions live at `~/.copilot/mcp-config.json`. In a trusted repository, Copilot CLI walks from the working directory to Git root for `.mcp.json` and also reads `.github/mcp.json`; nearer files beat farther files, `.mcp.json` beats `.github/mcp.json` in the same directory, and project definitions beat user definitions. Copilot CLI explicitly does not read `.vscode/mcp.json`. [Copilot CLI project discovery](https://docs.github.com/en/copilot/how-tos/copilot-cli/customize-copilot/add-mcp-servers#adding-per-repository-mcp-servers)
- **Enablement/cache.** Added servers become available immediately. `/mcp disable` applies only to the current session. Registry installation copies a definition into user config and starts it. The reviewed docs specify no persistent tool cache or automatic MCP package-update contract. [Copilot CLI management](https://docs.github.com/en/copilot/how-tos/copilot-cli/customize-copilot/add-mcp-servers#managing-mcp-servers), [registry installation](https://docs.github.com/en/copilot/how-tos/copilot-cli/customize-copilot/add-mcp-servers#searching-and-installing-from-the-registry)
- **Authentication storage.** The documented config directory assigns MCP OAuth token/registration fallback data to `~/.copilot/mcp-oauth-config/` and MCP secret fallback/index data to `~/.copilot/mcp-secrets/`. [Copilot CLI config directory](https://docs.github.com/en/copilot/reference/copilot-cli-reference/cli-config-dir-reference#directory-overview)
- **Local evidence.** `~/.copilot/mcp-config.json` owns the remote `notion-sentinel` definition. `~/.copilot/mcp-oauth-config/` exists and contains an OAuth metadata/credential-category file; no value was inspected or recorded. `agentlens` has no project Copilot MCP file.

### GitHub Copilot in VS Code 1.134.0

- **Discovery and scope.** Workspace config is `.vscode/mcp.json`; user config is the current VS Code profile's `mcp.json`. Dev containers can contribute MCP config, and `chat.mcp.discovery.enabled` can import definitions from selected other applications. VS Code Agent Host receives compatible forwarded config, but reads workspace `.mcp.json` and user `~/.copilot/mcp-config.json` natively. The reviewed page does not state collision precedence between same-name sources. [VS Code MCP configuration](https://code.visualstudio.com/docs/agent-customization/mcp-servers#_configure-the-mcpjson-file)
- **Enablement/cache.** Enable/disable state is stored separately from shared `mcp.json`. Configuration changes trigger rediscovery on restart, optionally automated by `chat.mcp.autostart`; the UI can start, stop, and clear cached tools. Cache path, TTL, and automatic invalidation are not documented on the reviewed page. [VS Code enablement](https://code.visualstudio.com/docs/agent-customization/mcp-servers#_enable-or-disable-mcp-servers), [autostart](https://code.visualstudio.com/docs/agent-customization/mcp-servers#_automatically-start-mcp-servers)
- **Authentication storage.** First-party docs recommend input variables or environment files and provide an OAuth UI, but do not identify the token store. Direct inspection found Notion MCP cache and dynamic-auth registration categories plus an MCP encryption-key category inside `~/Library/Application Support/Code/User/globalStorage/state.vscdb`; no value was read or recorded.
- **Local evidence.** `~/Library/Application Support/Code/User/mcp.json` owns the remote `notion` definition. Its `mcpToolCache` contains only that Notion server. `agentlens` has no `.vscode/mcp.json`.

### Pi 0.80.2 with `pi-mcp-adapter` 2.10.0

- **Discovery and precedence.** The installed adapter's first-party README says it reads shared user `~/.config/mcp/mcp.json`, Pi user `<agent-dir>/mcp.json`, project `.mcp.json`, and project `.pi/mcp.json`, in that order with later definitions winning. Host-specific configs are scanned only by the explicit setup/adoption flow. [Adapter 2.10.0 quick start](https://github.com/nicobailon/pi-mcp-adapter/blob/v2.10.0/README.md#quick-start), [adapter file layout](https://github.com/nicobailon/pi-mcp-adapter/blob/v2.10.0/README.md#file-layout)
- **Enablement/cache/lifecycle.** Servers are lazy by default, with `lazy`, `eager`, and `keep-alive` lifecycle choices and an idle timeout. Tool metadata is cached in `<agent-dir>/mcp-cache.json`; direct tools can register from that cache without connecting. Pi-specific overrides are written to Pi-owned files instead of rewriting adopted source config. [Adapter lifecycle](https://github.com/nicobailon/pi-mcp-adapter/blob/v2.10.0/README.md#lifecycle-modes), [metadata cache](https://github.com/nicobailon/pi-mcp-adapter/blob/v2.10.0/README.md#direct-tools)
- **Authentication storage.** The adapter supports bearer/environment interpolation and OAuth. Current upstream documents OS credential-store persistence with server-name and URL binding; the installed files contain no plaintext Pi MCP source config. [Adapter authentication](https://github.com/nicobailon/pi-mcp-adapter#authentication)
- **Adapter package pin.** Pi's `settings.json` requests the mutable source `npm:pi-mcp-adapter`; the generated `~/.pi/agent/npm/package.json` uses the range `^2.10.0`, while its lockfile resolves 2.10.0 with an integrity hash. This pins the currently materialized adapter install, not the declaration used by a future package update. Pi supports exact npm versions and git tag/commit refs; pinned git refs are skipped by bulk package updates. [Pi package syntax and update behavior](https://github.com/badlogic/pi-mono/blob/main/packages/coding-agent/README.md#pi-packages)
- **Local evidence.** There is no `~/.config/mcp/mcp.json`, `~/.pi/agent/mcp.json`, or `agentlens/.mcp.json`/`.pi/mcp.json`. `~/.pi/agent/mcp-cache.json` nevertheless contains tool metadata for `confluence-hdir`, and `mcp-npx-cache.json` contains a resolved historical `mcp-remote` 0.1.38 command for the Atlassian endpoint. With every documented source absent in the current directory, both are cache-only here; their originating source is unresolved. A separate project, `~/source/hdir/platform/vision/.pi/mcp.json`, owns a Pi-specific `confluence-local` definition only when Pi runs in that project.

## Pinning options and limits

| Mechanism | Supported use | What it actually guarantees | Limit |
|---|---|---|---|
| Exact npm spec, e.g. `package@1.2.3` in stdio args | Any client that passes literal command arguments to `npx`/npm; explicitly shown by Pi and the Pi adapter. [npm](https://docs.npmjs.com/cli/v11/using-npm/package-spec), [Pi packages](https://github.com/badlogic/pi-mono/blob/main/packages/coding-agent/README.md#pi-packages), [Pi adapter example](https://github.com/nicobailon/pi-mcp-adapter#quick-start) | Selects an exact registry version at resolution time. A generated npm lockfile can additionally record tarball integrity for an installed adapter dependency. | MCP clients do not themselves enforce a shared lockfile. Registry availability/trust and transitive dependency behavior remain runtime/package-manager concerns. |
| npm tag/range/unversioned spec (`@latest`, `^2.10.0`, or no suffix) | Accepted by npm and observed locally. [npm](https://docs.npmjs.com/cli/v11/using-npm/package-spec) | Expresses a moving selector or allowed version set. Existing npx cache may temporarily reuse one resolution. | Not a reproducible pin; clearing/expiring cache or updating can resolve a different version. |
| Pi package `git:...@ref` or URL `@ref` | Pi extension/package installation. [Pi packages](https://github.com/badlogic/pi-mono/blob/main/packages/coding-agent/README.md#pi-packages) | A full commit ref can identify immutable source; a tag/branch is only as stable as the remote ref policy. Pi skips pinned refs during bulk package update. | Pins the Pi adapter/package, not MCP servers that the adapter later launches unless their definitions are also pinned. |
| Absolute executable/build path | All stdio clients accept literal command paths. | Fixes which local path is launched. | Does not establish provenance, version, commit, or content integrity; the file can change in place. |
| Exact remote MCP URL | All reviewed remote-capable clients accept a literal URL. | Fixes scheme/host/path and can select a provider's versioned route if it offers one. | No reviewed client verifies an implementation digest. Hosted behavior and tool schemas can change behind the same URL. ChatGPT's frozen schema snapshot controls approval drift, not endpoint implementation. [ChatGPT snapshot](https://help.openai.com/en/articles/12584461-developer-mode-and-mcp-apps-in-chatgpt#do-mcp-app-changes-auto-update-in-my-workspace) |
| Container image digest or locally verified binary checksum | Could be embedded in a stdio command if the chosen runtime supports it. | Can identify immutable executable content when supported and enforced by that runtime. | This is outside the reviewed clients' MCP configuration contract; none documents MCP-specific digest resolution or verification. |

## Remaining uncertainty

1. The source that originally populated Pi's `confluence-hdir` metadata and unversioned `mcp-remote` cache is absent from all adapter sources relevant to `agentlens`; only cache evidence remains.
2. No declaring source was found for an “Svelte MCP.” The installed Svelte VS Code extension is not enough to infer one.
3. VS Code documents that enablement and cached tools are stored separately, but not cache TTL, collision precedence, or physical OAuth-store details.
4. Codex documents stored MCP OAuth but does not identify the backing physical store. Classic Claude Desktop and ChatGPT web likewise do not publish physical MCP credential-store locations in the reviewed sources.
5. Live documentation and hosted endpoints are mutable. This report records behavior and installed state as of the evidence date; it does not select the final retained owner or modify any configuration.
